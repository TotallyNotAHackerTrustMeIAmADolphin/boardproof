# Schematic construction workflow

**ERC-clean is not the same as correct, and neither one means readable.** Both halves of that have already cost this project a rebuild, so treat them as two separate checks you owe every schematic you touch:

1. **The walk from a fetched part to a wired symbol: one tool per step, in this order.** Steps a and b belong to the `library` toolset (the kicad-sourcing skill has the details); the rest is this toolset.
   - a. `propose_adopt_parts` once with every part of the batch: the datasheet is mandatory (a symbol that has none needs `datasheet` in its part, else that part and with it the whole call is rejected).
   - b. `confirm_adopt_parts` with the token: it writes a NEW revision folder (`<project folder>_adopted` beside the source unless `output_dir` was given to `propose_adopt_parts`), leaves the source untouched and returns the revision's board as `pcb_path`. The revision holds a copy of the project with its schematic, so every later call uses the schematic in that folder, never the source.
   - c. `add_symbols` with the adopted `lib_id` (`project_parts:<symbol name>` unless `library_name` was set): a placed symbol takes over the Footprint, Datasheet and LCSC of its library symbol (item 2), so an adopted part arrives with its Footprint. A placed symbol has an empty Footprint only when its library symbol has none (`Device:R` has none): that stays empty until `assign_footprints`.
   - d. `check_symbol_fields` lists the placed symbols whose Footprint, LCSC or Datasheet is missing or empty; `get_properties` reads the values.
   - e. `assign_footprints` with one `{reference: footprint_id}` mapping for every symbol that still has no Footprint (`set_properties` for the other fields).
   - f. `get_symbol_pins`, then `connect_pins` (item 13). A turn by 180 degrees reverses the pin order: for `Device:R` pin 1 is the top pin at rotation 0 and the bottom pin at rotation 180. The side of a pin inside the symbol's drawing is a property of the library symbol, so only rotation and mirror of the instance change it (`rotation` and `mirror` of `add_symbols`, later `rotate_items` and `mirror_items`, item 10); look at `get_symbol_pins` before you wire.
   - g. `add_no_connects` marks the pins that stay open, found from the netlist (`add_labels` with kind `no_connect` puts one marker at a point you give).
   - h. `sch_run_erc` (`verification` toolset); for a hierarchical project `check_project`; `diff_schematic` compares symbols and nets with an earlier state (another path or a git revision).

   `add_symbols`, `add_wires`, `add_labels`, `connect_pins`, `rotate_items`, `mirror_items`, `replace_symbols` and `add_no_connects` take `dry_run`: use it first when the result is not obvious; the first four also return `nets`, the net change they would make, and with `scope` "sheet" (a sheet a parent uses) a join through the parent sheet is not seen. A placeholder placed early becomes the adopted part with `replace_symbols` and `library_fields: true` (item 15; without that option the symbol keeps its own Footprint text), a note beside a part is `add_text`, and `rename_ref` and `rename_net` (item 17) change names without relabelling by hand.

2. **Build in batches.** `add_symbols`, `add_wires`, `add_junctions`, `add_labels` and `assign_footprints` all take a list of specs and place the whole set in one call (`add_symbols` also takes `mirror`: `"y"` flips a symbol left to right, `"x"` top to bottom, rotation applied first; a spec key it does not know is refused as `invalid_spec`, nothing written; like a symbol placed by hand in KiCad it takes over every field of the library symbol (Footprint, Datasheet, Description, LCSC, custom fields, hidden state kept) and the library Value unless `value` is given; `footprint` and a `properties` map `{field: text | {value, hidden}}` override, and `replace_symbols` does the same only with `library_fields: true`) — never loop them one symbol/wire/label at a time. `assign_footprints` takes the entire `{reference: footprint_id}` mapping at once. `fix_annotation` renumbers every duplicate/missing reference designator across the sheet in a single pass.

3. **Be deliberate about `snap` — this is the one that fails silently.** Every underlying `kicad_tools` add-wire/add-label/add-power call grid-snaps its coordinates by default. When you pass a pin's *exact* coordinates and that pin isn't itself on-grid, the endpoint is silently moved off the pin: the wire or flag is added, no error is returned, and the intended connection simply never exists. That happened here for real (2026-09-02) — a power-flag symbol meant to drive a chip's VCC pin landed on an unconnected phantom net, and ERC reported "Input Power pin not driven by any Output Power pins" with nothing pointing at the actual cause. Since issue 86 `add_wires` and `add_labels` land a point that is within 0.01 mm of a pin, label, junction, sheet pin, no-connect marker or wire end exactly on it (what is on the sheet wins over the grid) and round every other point to the 1.27 mm grid; the result lists `snapped`, `landed_on_pin` and `grid`. `"snap": false` moves nothing at all, not even next to a pin, for a free end that is off the grid on purpose. Better still, do not type pin coordinates: wire by pin with `connect_pins` (item 13).

4. **Render it and actually look at it.** A schematic can pass ERC and still be unusable: the golden-path board's first version was ERC-clean and a human took one look at the rendered PDF and called it awful — diagonal wires slashing across the sheet, overlapping unreadable runs. ERC never complains, because a diagonal wire is electrically identical to an L-shaped one. That is now fixed at the source (`add_wires` defaults to `"route": "orthogonal"`, emitting L/Z right-angle paths and leaving a pin along its own axis; `"route": "direct"` is the old single-segment behaviour and should only be used deliberately) — but the *habit* is the durable part: call `render_schematic_diagnostic` from the `diagnostics` toolset and look at the result before declaring a schematic done. It returns `authoritative: false` for a reason — it is not a correctness check, exactly as ERC is not a readability check. Neither one substitutes for the other. To look closely at one dense corner use `render_region` (diagnostics toolset): `x1, y1, x2, y2` in the sheet's own millimetres (the numbers of the file, y downwards from the top-left of the page) and `dpi` (50-600) give a PNG of just that area; it is a visual aid, never evidence.

5. **Run the readability checker; it is not an MCP tool.** `boardproof.schematic_readability` is a read-only module with a command line, so run it from a shell: `python -m boardproof.schematic_readability <root.kicad_sch | directory>` (a directory is searched for projects; every sheet reached from the root sheet is graded). It prints PASS or FAIL per sheet with the count per rule: `symbol_overlap`, `text_overlap`, `wire_not_orthogonal`, `wire_off_grid`, `net_unlabelled_between_blocks`, `value_not_visible` and `model_name_not_visible`. Text sizes are estimates and a pass means only "no rule violated", so it complements the render in item 4 and does not replace it. It is also not ERC (item 6).

6. **Check connectivity, then run the authoritative ERC.** `check_connectivity` is the fast narrow check (unconnected pins, floating wire endpoints) — run it right after wiring, while the cause of a problem is still obvious. `sch_run_erc` in the `verification` toolset is the authoritative one; a design isn't clean until that says so. For a whole hierarchical project use `check_project` (read-only, no lock; optional `root_sch` and `checks`, a list of `connectivity` and `erc`): one call over the sheet tree, one `kicad-cli` ERC run on the root, the findings grouped per sheet file with counts per sheet and in total. A sheet that cannot be loaded is listed under `sheet_problems` and makes the result `incomplete` (never silently dropped); `no_findings` is true only when both checks ran, every sheet loaded and nothing was found, and is not a verdict on the board. Neither reports an empty Footprint, a missing LCSC or a Datasheet of `~`: `check_symbol_fields` (read-only, no lock; optional `required_fields`, default Footprint, LCSC and Datasheet) lists them in one call over the whole sheet tree, per sheet file by reference and uuid, with the problem per field (`missing`, `empty`, `blank`, `placeholder`; a wrong-case name such as `Lcsc` under `case_variant`). Power, off-board and DNP symbols are not checked and are listed apart under `skipped`. Repair the gaps with `set_properties`; `no_gaps` is not a verdict on the board. To read the values themselves (for example the LCSC, Footprint and Value of every part, or of chosen references or uuids), use `get_properties` (read-only, no lock; optional `references`, `uuids` and `properties`, default Value, Footprint, Datasheet, Description and LCSC): per sheet file by reference and uuid, a requested name the symbol lacks is listed under `absent`. If you want proof that the connections you *meant* to make actually exist, export a netlist (`export_spice_netlist`, or `kicad-cli sch export netlist`) and read it — that is what caught the snapped-off-pin bug in the first place. To see what a rework or a branch changed, use `diff_schematic` (read-only): symbols added, removed, changed (field by field) and moved, per sheet file, and nets added, removed, renamed or with other pins, for the whole project (each net with the sheet path its name carries), between two paths or between a git revision and the working files or another revision (`before_revision`, `after_revision`); a state that does not load is reported and nothing is compared. It compares only symbols and nets: a label, text, wire, junction, sheet symbol, graphic or title block change that alters no net is NOT seen, so `no_symbol_or_net_differences` does not mean the sheets are the same; it is no ERC and no verdict.

7. **Hierarchical (multi-sheet) projects: the tools that place symbols are guarded.** A symbol placed on a sub-sheet needs instance data that names where the sheet is used. `add_symbols` and `add_labels` with kind `power` attach it from the project tree and report it as `instance_data` (`reattached`, `reason`, `note`); when the project cannot prove where the sheet is used they refuse with `unproven_instance_data` (`instance_reason`: `tree_problems`, `root_not_found` or `walk_failed`) and write nothing. Wires, junctions, labels and no-connects hold no instance data. Read `instance_data` in the result (docs/ARCHITECTURE.md, "Known facts and gotchas").

8. **Never hand-edit the `.kicad_sch`.** Even for a "small fix" — see the always-loaded rule in CLAUDE.md. And when deriving a PCB from the schematic, make sure `kicad-cli` is resolvable first (`ensure_kicad_cli_on_path()`): `kicad_tools.schema.PCB.from_schematic()` silently falls back to a pure-Python netlist extractor that once merged a chip's VCC and GND pins onto a single mis-named net — a plausible-looking derived board that would have been a real short.

9. **Rework a sheet in place; do not reset it to its skeleton.** `delete_symbols`, `delete_wires`, `delete_labels` and `delete_junctions` select by reference, text, uuid, shell pattern or region (a wire also by `net`, the label text it is joined to), `move_symbols` and `move_labels` take an absolute `to` or a relative `offset`, and `set_property_positions` sets the position, angle and justification of Reference, Value and other property texts. All are batch tools. Every call compares kicad-cli's netlist before and after on a scratch copy and refuses with `connectivity_changed` when a net would split, merge, lose a pin's company or change its name; pass `allow_connectivity_change` only when that is the intent, and read the listed changes. `dry_run` shows the result without writing. A delete reports the wires, junctions and labels it left dangling (`remove_dangling` removes wires and junctions). A moved symbol drags the wire ends, junctions, labels and no-connect markers sitting on its pins (`move_wires`, default true) and lists the wires that became slanted; positions snap to 1.27 mm unless `snap` is false, and the result lists what was snapped and the new pin positions, so a wire can be drawn to them without guessing. Instance data is not touched, so these work on a sheet a parent sheet uses. To tidy a sheet use `align_items` (groups of `{kind: symbol|label, references|texts|uuids, edge: left|right|hcenter|top|bottom|vcenter, reference: first|last|min|max|a coordinate}`) and `distribute_items` (`{kind, references|texts|uuids, axis: x|y, spacing: gaps|centres|a pitch in mm}`, at least three items): the lists name the items one by one (`first` and `last` follow your list), symbol boxes come from the raw library geometry of the sheet (the symbol's graphics plus its visible pins' connection points and lines; texts inside the library symbol, pin texts and property texts are not counted; `box` accepts `pins` only), a label is its anchor point, texts and attached wire ends follow, origins snap to the grid so the result lists each item's `residual` and each group's `aligned` or `even`, and the same connectivity comparison and `dry_run` apply. Wires and junctions are not items of these tools; they follow the symbols or labels they touch. To change the text of labels and free text objects that exist, use `set_text` (items `{uuid | kind + old_text [+ point], text}`; kind is label, global, hier or text): it keeps uuid, position, rotation, shape and effects. Renaming a net label is a connectivity change and is refused with `connectivity_changed` unless `allow_connectivity_change` is true; a free-text change never is. A renamed hierarchical label leaves the parent's sheet pin alone and the result lists a `pin_name_mismatch` warning: rename the pin with `remove_sheet_pins` and `add_sheet_pins`.

   To add a note or a pin annotation (for example `U501.24 VDD` beside a decoupling capacitor) use `add_text`, never `add_labels`: a label names a net, a free text joins nothing. Items `{x, y, text [, rotation 0|90, size, justify]}`, one line each (a line break or tab is refused), positions snap to 1.27 mm unless `snap` is false; it returns each text's `uuid`, which `set_text` takes to change it later. The netlist and the ERC census are compared before and after and must be unchanged; there is no override.

10. **Turn or mirror placed symbols with `rotate_items` and `mirror_items`, never by editing the angle.** Both take `items`, each a symbol selector (`references`, `uuids`, `pattern`, `region`, `lib_id`; every unit of a reference is picked) plus `by` (90, 180 or 270, counter-clockwise as seen on the screen) or `to` (the stored angle 0, 90, 180 or 270) for `rotate_items`, and `axis` for `mirror_items` ("x" swaps top and bottom, "y" swaps left and right; mirroring again about the same axis undoes it). The symbol keeps its origin; the wire ends, junctions, labels and no-connect markers that sit exactly on a pin follow that pin to its new place (`move_wires`, default true) and the wires that end up slanted are listed under `slanted`; the property texts keep their offset from the origin turned with the symbol (`property_texts: "keep"` leaves them; their own angle and justification are not changed, so check them with `set_property_positions`). The origin does not move, so nothing snaps; pins that land off the 1.27 mm grid are listed under `off_grid_pins`. The same netlist comparison as the move tools refuses a change that alters a net (`connectivity_changed`), and a drag that would lay a wire over a pin, label or other wire end is refused as `drag_crosses_connection`: a 180 degree turn of a two-pin part wired on both sides is such a case, rewire it with `connect_pins` after turning it with `move_wires` false and `allow_connectivity_change`. Rotating a part rarely leaves its wires straight; look at `slanted` and redraw those. `dry_run` shows the new pin positions first.

11. **Look for overlaps and off-grid points with `find_overlaps` and `snap_to_grid`.** `find_overlaps` is read-only over the whole project and lists symbols whose boxes overlap, texts on texts, on symbols and on wires (text boxes are estimates and say so), and wires that run over a pin without ending there or having a junction (KiCad joins a pin only to a wire end or a junction, so such a pin joins nothing). `snap_to_grid` finds the pins, wire ends, labels, junctions and no-connect markers of one sheet that are off the 1.27 mm grid (ERC only reports them) and moves them: a symbol moves as a whole with its texts, what sat on a moved pin follows, and a snap that would change a net is refused with `connectivity_changed` (no override; narrow `kinds`). Use `dry_run` first; a symbol whose pins cannot all reach the grid is listed under `unsnappable` and not moved.

12. **Repeat a circuit with `replicate_group`.** To repeat a circuit (a relay with its two resistors, ten branches on a 17.78 mm pitch) use `replicate_group`, never ten rounds of `add_symbols`, `add_wires` and `add_labels`: `region {x1, y1, x2, y2}` is the group (everything wholly inside it; an object that crosses the edge is refused as `crosses_region`), `copies` is the number of NEW copies (the original stays as branch 1), `pitch {dx, dy}` must be a multiple of the 1.27 mm grid. References continue from the highest used per prefix in the whole sheet tree (R7 elsewhere: the copy's R1 and R2 become R8 and R9); local labels that end in digits count up (`OUT1` becomes `OUT2`; `numbered_labels` takes a list of texts or `[]`), every other label keeps its text, so global labels and ground symbols are shared by the copies. On a sheet a parent uses each use path gets its own new reference. A copy that would touch an existing object, leave the page or run into an existing label text is refused with nothing written; kicad-cli's netlist must equal the netlist before plus exactly the copies, else `write_not_verified`. `dry_run` lists the references and labels that would be made.

13. **Wire by pin, not by hand-computed offsets.** `get_symbol_pins` (read-only, batch: a list of `references`, shell patterns allowed, `*` for every placed symbol on this sheet (child sheets are not followed), and/or a list of `uuids`, which picks one symbol even when several share a reference) returns each placed symbol's pins with number, name, electrical type and the absolute sheet coordinates a wire end or label must sit on, with rotation and mirror applied; a multi-unit part gives one entry per placed unit. On a sheet used more than once, `reference` is the sheet's own property, not the per-use reference. Pass `snap: false` when using those points in `add_wires` and `add_labels`. `add_symbols` reads back every symbol and unit it wrote (`symbols`: reference, uuid, unit, `at`, rotation, each pin's number, name and point, `off_grid_pins`); it places at the coordinates given and rounds the origin to the grid only for a spec with `"snap": true`. `connect_pins` is the batch tool for wiring: a list of `{from, to}` where an end is `"R1.2"` or `{ref | uuid, pin, unit}` (a multi-unit pin name that exists in several units is refused as `pin_ambiguous`: give `unit`). It resolves both pins, tries a straight, L, Z and U path that leaves each pin along its own direction, and draws it. Pin points stay exact, on the grid or not; points the tool chooses itself (a Z or U line, `via` waypoints) are snapped to the grid, and the result lists them (`snapped`, `off_grid_endpoints`). A path over another pin, label, junction, no-connect or sheet pin, or touching another wire, is not drawn: the call is refused as `no_clear_route` and names the blocker, and `via` ([[x, y], ...], orthogonal legs) chooses the path yourself. The tool adds the junction a wire end needs when it lands on the middle of another wire. Symbol bodies are not checked: render the sheet. Every call compares kicad-cli's netlist before and after: each requested pair must be on one net (else `write_not_verified`), and an unrequested merge or two differently named nets joined is refused as `connectivity_changed` unless `allow_connectivity_change`. A pair that is already on one net is skipped. `net_label` names the net, `dry_run` plans and checks without writing. Parts side by side whose pins face the wrong way round (for example R1.2 leaving down to R2.1 leaving up) may give `no_route`: pass `via` waypoints. A sheet used more than once is refused as `pin_not_in_netlist`.

14. **Change the pins of a sheet symbol that already exists.** `add_sheet_symbols` only takes sheet files no sheet symbol uses yet. For a sheet symbol already on the parent sheet use `add_sheet_pins` (a list of `{sheet | uuid, pins: [{name, direction, side?, offset?}]}`; direction is input, output, bidirectional, tri_state or passive; side defaults to left, right for output; offset is mm along the edge, snapped to the 1.27 mm grid, strictly inside the edge, never on another pin), `remove_sheet_pins` (`{sheet | uuid, pins: [names], pattern?}`; a symbol may end up with no pins) and `move_sheet_pins` (`{sheet | uuid, pins: [{name, side?, offset?}]}`, along the edge or to another side). `add_sheet_pins` creates the hierarchical label of the same name and direction in the child sheet, or reuses one that has it; a label of the same name with another direction is refused as `label_direction_mismatch`, a pin name the symbol already has as `duplicate_pin_name`. `remove_sheet_pins` leaves the child's label alone unless `remove_child_labels` is true (the result says `left`, `removed` or `absent` per pin); a label without a pin is an ERC error until it is removed or its pin is added again. The result lists each pin's absolute position (`at`) on the parent sheet: `get_symbol_pins` and `connect_pins` cannot address a sheet pin, so draw to that point with `add_wires` (it lands a point within 0.01 mm of a sheet pin exactly on it). A pin with a wire, label, junction or symbol pin on it cannot be removed or moved, and a new pin cannot land on one, without `allow_connectivity_change` (`connectivity_changed`, nothing written, the attached items listed); a wire is not dragged along with a moved pin. Every call is built on scratch copies first (every node it did not select unchanged, the child's symbols and instance data included; kicad-cli ERC and netlist compared before and after) and `dry_run` returns the same report without writing. To bring the pins in line with the child's hierarchical labels: `compare_sheet_pins` (read-only, no lock; optional `sheets` names or uuids) lists per sheet symbol `missing_pins` (a label with no pin, with its direction), `missing_labels` (a pin with no label), `direction_mismatches` (kicad-cli's ERC does not report these) and `duplicate_labels`; `sync_sheet_pins` creates the missing pins from the labels (name and direction of the label) with the checks of `add_sheet_pins`, and never creates or removes a label, changes a direction or removes a pin: those come back under `unresolved` for you to decide. A second call with nothing to create writes nothing.

15. **Replace a placed symbol by another library symbol (a placeholder by the final part).** `replace_symbols` takes a list of `{reference | uuid, lib_id, pin_map?}` and swaps the `lib_id` and the embedded library symbol of each symbol in place: uuid, reference, position, rotation, mirror, unit, property texts and instance data stay as they are, so nothing is deleted and placed again. `lib_id` is read from the project's symbol library table or KiCad's own folder. Pins are paired by pin number (by pin name for a pin without a number); `pin_map` ({old pin number: new pin number}) pairs pins whose numbers differ. Wires are never dragged: a wired pin with no counterpart is refused as `pin_unmapped` (nothing written, the pins listed), a wired pin whose counterpart lies at another point and a new pin that lands on a wire end, label, junction or pin are refused as `connectivity_changed` with the old and new positions, and kicad-cli's netlist is compared before and after on a scratch copy; pass `allow_connectivity_change` only when that is meant. The old library symbol is dropped only when no other symbol uses it (`dropped_library_symbols`, `kept_library_symbols`). The result lists each new pin's absolute point, so wires can be drawn to the extra pins of the final part. A part with several units placed and a unit the new symbol lacks are refused (`multi_unit_symbol`, `unit_missing`). Value, Footprint and Datasheet keep their old text. `dry_run` returns the same report as `would_replace` and writes nothing.

16. **Mark open pins with a no-connect, by pin.** `add_no_connects` takes `selectors` (`{references | uuids, pins}`; `pins` is a list of pin numbers or `"unconnected"`, the default; no selectors at all means every placed symbol of the sheet) and puts a marker exactly on each chosen pin point, so ERC stops reporting `pin_not_connected` for them. Open means kicad-cli's netlist lists the pin alone on an `unconnected-(..)` net, not a geometry guess: a wire that only runs over a pin leaves it open. `"unconnected"` skips pins of the type `no_connect` and `#` power symbols (hidden pins of one name sit in a shared net, so they are not open and are not listed); a pin named explicitly that is wired, labelled or tied to another pin (including a hidden pin of the same name) is refused as `pin_connected`, a hidden one as `pin_hidden`, a power symbol pin as `power_symbol_pin`; a pin that already has a marker is listed under `already_marked`; the result keeps each pin `type` and counts under `silenced_other_erc` the `input` and `power_in` pins whose `pin_not_driven` or `power_pin_not_driven` the marker also silences. The call refuses unless the netlist is unchanged and ERC shows exactly as many fewer `pin_not_connected` as pins marked (`write_not_verified`). `delete_no_connects` removes markers by `uuids`, `region`, `points`, or `references` plus `pins`; `delete_labels` does not take the kind. Both support `dry_run`, `allow_connectivity_change` and `root_sch`.

17. **Rename a net or a reference with `rename_net` and `rename_ref`, never by editing labels one by one.** Both take `renames`, a list of `{old, new}`, and change every place that carries the name across the whole sheet tree in one transaction. `rename_net`: `old` is the net as kicad-cli's netlist names it (`VCC`, `/SDA`, `/Sub/SDA`), `new` is the new name without a sheet path (the net keeps its scope). A name without a leading slash renames every global label with that text and every power symbol whose Value is that text; `/<sheet path>/<text>` renames the local and hierarchical labels on that sheet, and for a hierarchical label also the sheet pins of that name on the parent sheet symbols. A sheet pin that is only wired to a renamed label keeps its own name. A new name that already exists is refused (`name_exists`); `merge: true` joins the two nets and the result says so under `connectivity.merged` (connectivity changes only then). A net-class rule of the project file that would stop matching is refused (`net_rule_orphaned`; the project file is not edited here; `allow_orphaned_net_rules` renames anyway and lists the rule). A local name on a sheet file that two sheet symbols use is refused (`sheet_used_more_than_once`). `rename_ref`: every unit of a multi-unit part on every sheet, in the instance data KiCad reads and in the Reference property; a reference another part has is `reference_exists` (never merged); a sheet file used twice has one reference per use and only the use that carries the old reference changes; instance data that cannot be shown to be the one KiCad reads is `instance_data_unproven`. Both compare kicad-cli's netlist before and after (equal modulo the rename) and refuse with `write_not_verified` otherwise; `dry_run` runs all checks and writes nothing. The board keeps the old names until it is updated from the schematic.

18. **Put fields on placed symbols with `set_properties`.** A batch call `set_properties(sch_path, items)` where each item is `{reference | uuid, set: {name: value | {value, hidden?}}, remove: [names]}` sets, adds or removes instance properties (LCSC, MPN, Datasheet, Description, Value, Footprint, any custom name) without rebuilding the sheet. A property the symbol has keeps its position, font and place (only the value changes); a new one is put at the symbol's own origin, hidden unless `hidden` is false (move a shown one with `set_property_positions`). The Reference cannot be set here (`reference_not_settable`; `fix_annotation` owns it) and neither the Reference nor the Value can be removed (`property_not_removable`; removing the Footprint works and the result carries a note). The units of a multi-unit part are edited together, by reference or through any one unit's `uuid`, because KiCad reads the fields from one unit's copy; the result lists each unit. Separate symbols that share a reference are `ambiguous_reference`: pick one by `uuid`. A part with a unit on another sheet is `part_spans_sheets`. The sheet must be tied to one readable project (`root_sch`, or the one project within 12 folders above whose tree holds the sheet), otherwise `root_not_found`; `standalone: true` is the explicit way out and means units on other sheets are not checked (the result says `part_checked_standalone`), for example for a new sheet that no sheet symbol uses yet; it costs a possible refusal, not a silent edit: KiCad may keep reading the other unit's copy, and then the netlist check refuses the call as `write_not_verified`. Every call compares kicad-cli's netlist of the edited project with what was asked (found by the instance reference of each sheet use) and refuses with `write_not_verified` when the netlist does not follow. The netlist is compared before and after, so changing the Value of a power symbol (it names its net) is refused with `connectivity_changed` unless `allow_connectivity_change` is true. `dry_run` writes nothing.

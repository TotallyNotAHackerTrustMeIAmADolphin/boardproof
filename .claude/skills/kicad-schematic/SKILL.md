# Schematic construction workflow

**ERC-clean is not the same as correct, and neither one means readable.** Both halves of that have already cost this project a rebuild, so treat them as two separate checks you owe every schematic you touch:

1. **Build in batches.** `add_symbols`, `add_wires`, `add_junctions`, `add_labels` and `assign_footprints` all take a list of specs and place the whole set in one call — never loop them one symbol/wire/label at a time. `assign_footprints` takes the entire `{reference: footprint_id}` mapping at once. `fix_annotation` renumbers every duplicate/missing reference designator across the sheet in a single pass.

2. **Be deliberate about `snap` — this is the one that fails silently.** Every underlying `kicad_tools` add-wire/add-label/add-power call grid-snaps its coordinates by default. When you pass a pin's *exact* coordinates and that pin isn't itself on-grid, the endpoint is silently moved off the pin: the wire or flag is added, no error is returned, and the intended connection simply never exists. That happened here for real (2026-09-02) — a power-flag symbol meant to drive a chip's VCC pin landed on an unconnected phantom net, and ERC reported "Input Power pin not driven by any Output Power pins" with nothing pointing at the actual cause. **Pass `"snap": false` in any spec whose coordinates must land exactly on a pin**; leave the default on for tidy routing between points that don't need to be exact.

3. **Render it and actually look at it.** A schematic can pass ERC and still be unusable: the golden-path board's first version was ERC-clean and a human took one look at the rendered PDF and called it awful — diagonal wires slashing across the sheet, overlapping unreadable runs. ERC never complains, because a diagonal wire is electrically identical to an L-shaped one. That is now fixed at the source (`add_wires` defaults to `"route": "orthogonal"`, emitting L/Z right-angle paths and leaving a pin along its own axis; `"route": "direct"` is the old single-segment behaviour and should only be used deliberately) — but the *habit* is the durable part: call `render_schematic_diagnostic` from the `diagnostics` toolset and look at the result before declaring a schematic done. It returns `authoritative: false` for a reason — it is not a correctness check, exactly as ERC is not a readability check. Neither one substitutes for the other.

3a. **Run the readability checker; it is not an MCP tool.** `kicad_mcp.schematic_readability` is a read-only module with a command line, so run it from a shell: `python -m kicad_mcp.schematic_readability <root.kicad_sch | directory>` (a directory is searched for projects; every sheet reached from the root sheet is graded). It prints PASS or FAIL per sheet with the count per rule: `symbol_overlap`, `text_overlap`, `wire_not_orthogonal`, `wire_off_grid`, `net_unlabelled_between_blocks`, `value_not_visible` and `model_name_not_visible`. Text sizes are estimates and a pass means only "no rule violated", so it complements the render in step 3 and does not replace it. It is also not ERC (step 4).

4. **Check connectivity, then run the authoritative ERC.** `check_connectivity` is the fast narrow check (unconnected pins, floating wire endpoints) — run it right after wiring, while the cause of a problem is still obvious. `sch_run_erc` in the `verification` toolset is the authoritative one; a design isn't clean until that says so. If you want proof that the connections you *meant* to make actually exist, export a netlist (`export_spice_netlist`, or `kicad-cli sch export netlist`) and read it — that is what caught the snapped-off-pin bug in the first place.

5. **Hierarchical (multi-sheet) projects: these tools are unsafe.** They are built on `kicad_tools`' high-level `Schematic`, and resaving a subsheet through it silently collapses every symbol's hierarchical instance path. Components then vanish from the netlist. Until the tools guard against this, edit hierarchical projects through the low-level `kicad_tools.schema.Schematic` API and verify with a fresh `kicad-cli` netlist export (docs/ARCHITECTURE.md, "Known facts and gotchas").

6. **Never hand-edit the `.kicad_sch`.** Even for a "small fix" — see the always-loaded rule in CLAUDE.md. And when deriving a PCB from the schematic, make sure `kicad-cli` is resolvable first (`ensure_kicad_cli_on_path()`): `kicad_tools.schema.PCB.from_schematic()` silently falls back to a pure-Python netlist extractor that once merged a chip's VCC and GND pins onto a single mis-named net — a plausible-looking derived board that would have been a real short.

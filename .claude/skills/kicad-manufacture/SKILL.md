# Manufacturing export workflow

**An exit code is not a deliverable, and DRC-clean is not the same as manufacturable.** Every step below exists because one of those two assumptions produced a plausible-looking package that wasn't orderable.

1. **Export the whole package in one call.** `export_manufacturing_package(pcb_path, output_dir, schematic_path=..., manufacturer="jlcpcb", lcsc_overrides=...)` produces gerbers, drill, BOM and CPL together — never call it once per output format. LCSC part numbers come from `lcsc_overrides` (`{reference: lcsc_id}`, fed by this project's own sourcing pipeline); the upstream auto-LCSC lookup is deliberately disabled, so an unfilled "LCSC Part #" column means nobody supplied one, not that the part doesn't exist.

2. **Verify the artifacts, don't trust the status.** The return value is evidence-gated (`ok` vs `partial` plus an `errors` list), but "the export ran" and "the package is complete" are different claims. Check that each returned path — gerber archive, BOM, CPL — actually exists and is non-empty, and check `lcsc_part_numbers_filled` against how many overrides you passed. **Then read the files.** On the golden ATtiny1616 board the export reports `status: ok` and produces all three artifacts, while the CPL lists only 4 of the board's 6 components: the two through-hole pin headers J1 and J2 are dropped as hand-solder parts. Nothing about the tool's return value says that. `panelize_board` is the model to imitate here — it reloads the panel it just produced, counts footprints, and refuses to report `ok` unless the panel really contains `rows x cols` copies of every source footprint, precisely because KiKit exiting 0 doesn't prove it made a panel.

3. **Run the real DRC before you export, and read more than the violation count.** Nothing in the export path gates on DRC. The golden board exports cleanly while being completely unrouted — `pcb_run_drc` returns `violation_count: 0` alongside **11 unconnected items**, and `get_unrouted_nets` reports 5 unrouted nets. A zero next to the word "violations" is not a fab-readiness verdict. Do not export a board as order-ready unless it has a `verify_board` PASS (docs/TESTING.md's acceptance gate: zero unconnected items, zero error-level DRC, all zones filled, from complete `kicad-cli` lists). `verify_board` is always available (no `load_toolset` needed), and every board-state output, including `export_manufacturing_package`'s, carries a `gate` field with its last verdict for that exact file: `verdict`, `board_sha`, `project_sha`, `verdict_board_sha`, `age_s`, `stale`, `note`. Anything other than `verdict: PASS` with `stale: false` means the board is not verified ready; say so plainly.

4. **Check the board against the fab, not just against itself.** DRC only proves a design satisfies *its own* rules — if those rules are looser than the fab's process, a fully DRC-clean board is unbuildable. `pcb_get_design_rules(pcb_paths)` reports the rules a board actually declares (netclasses, project constraints, `.kicad_dru`), `get_manufacturer_design_rules(manufacturer, layer_count, ...)` reports the fab's published capability floor, and `pcb_check_manufacturability(pcb_paths, manufacturer, ...)` compares them per rule. Treat its verdicts precisely: `below_fab_floor` is a real problem, but `board_rule_unspecified` and `not_published_by_fab` are **unverified gaps, not passes** — they downgrade the board to `partial` with `meets_fab_floor: null`, and reporting that as "manufacturable" is exactly the false-pass this project's evidence-gated-verdict rule forbids. Use `list_manufacturer_profiles` when the fab name is uncertain rather than guessing an alias.

5. **Panelize as one parameterized call, then re-verify.** `panelize_board` takes the whole panel specification at once (grid, spacing, mousebites vs. v-cuts, framing, tooling holes, fiducials) — never one knob per call. It runs real DRC on both the source board and the resulting panel so you can tell whether panelization *introduced* violations rather than inheriting pre-existing ones; report that difference, don't report the panel's raw count. If KiKit isn't installed it returns `status: incomplete` with install instructions and no output file — it never passes the source board off as a panel.

6. **Never hand-edit exported or KiCad files** to make an artifact look right. If the package is wrong, fix the board through the tools and export again.
